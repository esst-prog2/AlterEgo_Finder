# Process

How the promo page (Homework 9) was made: after each step, one row with the step, what the tool did, and what I decided.

| Step | What the tool did | What I decided |
|---|---|---|
| 1. Working rule | Saved the rule for this session and later ones, created this file and the branch `promo-page` from the latest `main`. | After each step from now on, commit, and add a row to PROCESS.md: the step, what the tool did, and what I decided. |
| 3a. Install Impeccable | Read the install steps on impeccable.style and checked the npm package matches its GitHub repo (pbakaus/impeccable). Installed version 4.8.2 into this project for Claude Code only, without automatic hooks (`npx impeccable install --project --no-hooks --providers=claude`): the skills, 4 agents and a 21 MB Windows program, which runs here. | Keep Impeccable out of git, since it is a tool for making the page, not part of the program. Turn its anonymous usage data off. |
| 2a. Install gstack | Cloned gstack (garrytan/gstack, v1.99.2.0) into the user-level skills folder, read its setup script, installed Bun 1.4.4 with winget because setup needs it, and ran `./setup`. It registered gstack's skills (including `/office-hours`) for Claude Code, downloaded a 123 MB headless Chromium, and added one Stop hook to the global Claude Code settings, after backing them up. `/cso` is unavailable without the C++ build tools. | Install Bun with winget. Run setup with its default options. |
| 2. Content with `/office-hours` (in progress) | Ran gstack's `/office-hours` in builder mode: offered four ideas for the page, searched the web for what works on developer and model-card pages, set six premises, got a second opinion from a fresh reviewer, proposed three approaches and wrote a design doc with draft text. An independent spec review ran two rounds (score 5, then 7 of 10): 8 issues fixed, 3 more fixed afterwards, 8 minor ones listed. | Goal: learning (builder mode). Lead: the receipts, with privacy as support. After the second opinion: open with what, who and how, then the receipts; use an LFW example instead of my own result. Approach: a receipts ledger. Keep my two photos in the repository. The public-figure pool is an optional step. Not yet approved: to be reviewed next session. |
| 2. Content with `/office-hours` (done) | Showed the full design doc with the draft text for each section, the receipts ledger and the reviewer's concerns, marked it approved, and saved a copy in `design-docs/promo-page-content.md` (outside `docs/`, which GitHub Pages will publish). | Approved the design doc as it is: the measured rows stay "record only" unless there is time for the optional measurement scripts, and the 8 minor review points get fixed while building the page. |
| 3a. Impeccable `init` | Loaded Impeccable's project context (no product record, no visual design yet), read the repository and the approved content design, asked me to confirm the product record and the stack, and wrote PRODUCT.md: users, purpose, positioning, capabilities, evidence on hand, principles. No image generation here, so later steps design directly in code. | The product record is right as proposed. The page is plain HTML/CSS, one static page with no build step. |
| 3b. Impeccable `shape` | Asked three questions (what a visitor should believe, what would feel wrong, whether to keep the program's look), listed seven visual directions from the audience's world, ran Impeccable's roll (it assigned the archery scoresheet and dealt six catalogue challengers), weighed each challenger (one competitive, five declined, each declined one lending a discipline), showed them on a decision page in my browser, and wrote the brief in `design-docs/promo-page-brief.md`. No code. | Visitors should leave believing the labels. Ruled out: hype or startup gloss, and faces as decoration. Keep the program's label colours. Chose The Scoresheet on the decision page. Confirmed the brief. |
| 3c. First version of the page | Searched LFW with the real pipeline for a worked example (25 candidates), wrote the direction contract into Impeccable's surface brief, downloaded the open-licensed fonts (Barlow, Barlow Condensed, Kalam) into `docs/fonts`, and built `docs/index.html`: the similarity target drawn from the real data with a switch for the second photo, the scorecard header with copyable commands, how it works, the scorecard of seven claims, privacy, run it at home and the limits. Checked it in a headless browser on desktop and phone, and fixed label collisions, cut-off names and a too-wide phone layout. | Lennox Lewis as the worked example: top match Elvis Presley 0.2501 (Alter Ego), his second photo 0.7021 (Same person). |
| 3d. Impeccable `generate` | Started Impeccable's live mode on a local server for `docs/`, wrote three layout variants of the first screen (a masthead with the target beside Try it locally; three ruled columns; the name leading with Try it locally along the bottom), each with a density slider, and showed them in my browser. After each choice it made the accepted variant permanent, removed every preview marker, and checked the page on desktop and phone. | First accepted the name-leading variant, then asked to go back and choose again, and accepted the masthead variant, with the sliders at their defaults. |
| 3e. Impeccable `critique` | Ran two independent reviewers: a design review that walked the page as a classmate, the teacher and a stranger (plus first-timer, phone and keyboard personas) and scored the ten usability heuristics, and Impeccable's detector with an in-browser check. Combined them: 21 of 36 (58%, acceptable); the weakest part is the scorecard of claims. The detector's 6 padding warnings were false positives; no overflow, console errors or contrast failures. Saved the report for the next step. | See the next row for what to fix. |
| 3f. Fix the critique's P1 issues | Rewrote the scorecard in plain words (Claim, Predicted before the run, Measured, Source; "Not written down beforehand" where nothing was predicted) and removed its hover link to the target. Moved the switch, readout and a new legend under the target, with the legend saying what Alter Ego means (97% of strangers' best matches land there, so it is not a striking likeness). Gave Try it locally a Windows / macOS-or-Linux switch, full clone-to-run commands that wrap instead of clipping, and a phone link to them from the first screen. Checked in a headless browser: Copy gives the right commands for each system, no overflow at 1440 or 390 px, no console errors. | Fix the three P1s; use plain words but keep the scorecard look; explain Alter Ego at the target. |
